# 分阶段实施计划

## 通用规则

每阶段开始前重读四份设计文档、现有实现和测试命令，列出文件并确认路由与数据结构不变。每阶段结束后启动真实页面，检查 1440、1280、1024、768、390 宽度中该阶段要求的尺寸，运行现有测试与构建并停止等待确认。

## 阶段一：设计基础与应用骨架

目标：建立唯一语义设计变量、全局基础样式、AppShell、主导航视觉、页面容器、Button、IconButton、Loading/Empty/ErrorState；不迁移全部业务页面。

预计文件：

- 新增 `frontend/src/styles/tokens.css`
- 新增 `frontend/src/components/layout/AppShell.vue`
- 新增 `frontend/src/components/ui/BaseButton.vue`、`BaseIconButton.vue`
- 新增 `frontend/src/components/states/LoadingState.vue`、`EmptyState.vue`、`ErrorState.vue`
- 新增/更新对应单元测试
- 修改 `frontend/src/main.js`、`App.vue`、`style.css`、`components/NavBar.vue`

验收：只有一套活跃语义 token；现有路由仍可访问；导航、通知抽屉和移动菜单能力不丢失；1440×900、1024×768、390×844 无横向溢出；键盘焦点清楚；无无意义全局光标和滚动动画；测试、构建通过。

## 阶段二：核心图片画廊

目标：实现 `GalleryGrid`、`GalleryItem`、图片加载/失败/占位、真实比例适配、响应式布局、标题与必要元数据、键盘进入详情/查看器、空状态与分页。

主布局冻结为响应式 CSS Grid 的比例保真画廊：网格列宽分档，图片容器用后端真实宽高预留空间，默认完整展示或由场景明确声明缩略图 cover。可选布局为单列编辑式图片流；本阶段不默认引入 Masonry。

验收：混合横竖方图不拉伸；卡片优先 `thumbUrl -> mediumUrl -> original-compatible` helper；列表不主动加载全部原图；1440×900、1024×768、390×844 无明显 CLS/溢出；触屏和键盘有 hover 等效方式；测试构建通过。

## 阶段三：沉浸式图片查看器

目标：在现有 `ImageViewer` 上渐进增强为集合查看器，支持上一/下一、Esc、方向键、焦点锁定恢复、相邻预加载、缩放、拖动、全屏、移动滑动、信息面板与控件弱化。

验收：图片始终 contain 且不裁切；背景为中性 `#0e1216`；背景滚动锁定；关闭恢复触发点；切换不重建页面；reduced-motion 合规；真实浏览器完成鼠标、键盘、触屏检查；测试构建通过。

## 阶段四：图片详情、搜索与分类

目标：只基于现有字段与接口完善图片详情、作者/来源、时间、标签、分类、描述、EXIF、搜索、筛选、排序和真实图集入口。

验收：不存在的字段不渲染、不虚构；专业元数据渐进披露；筛选状态可理解和清除；URL 同步遵循现有路由；长标题/长描述/无字段状态可用；测试构建通过。

## 阶段五：响应式、性能与最终细化

目标：收口响应式、图片请求优先级、懒加载、现有 `srcset` 能力、首屏、相邻预加载、CLS、内存、键盘、焦点、对比度、状态与风格一致性。

验收：1440、1280、1024、768、390 全量检查；不存在列表误用原图、不必要重复请求、图片拉伸、明显布局偏移、无名按钮、hover-only、移动端横溢出、查看器无法退出或焦点丢失；全量测试、构建通过并输出最终报告。

## 风险与处理

- 旧 CSS 存在两套主题覆盖：阶段一建立单一 token 入口，按最小范围移除冲突，不对业务页全量重写。
- Element Plus 与新基础组件并存：业务弹窗暂保留 Element Plus；新基础组件只服务逐步迁移，不维护重复视觉 token。
- 后端可能不提供所有缩略图/宽高：使用现有 URL helper 与已知元数据；缺失时采用兼容占位，不虚构接口。
- 私有图片 token 可能过期：显示失败态并复用现有刷新/请求流程，不缓存私有原图。
- App 根节点受通知抽屉 transform 影响 fixed 定位：视口级浮层继续 Teleport 到 body。
