## 2. 总体目标

治理重点：

1. 修复广场图片抽屉滚动后脱离视口的问题。
2. 将登录与注册页面从深色霓虹式界面改为符合「和纸墨影」的明亮、克制布局。
3. 统一控件尺寸、层级、间距、面板宽度和浮层层级。
4. 根据内容关联建立页面结构，不再依靠大量边框、卡片和零散信息制造层次。
5. 清理未定义设计变量和残留旧主题规则。
6. 分阶段拆解过大的页面组件，并补足测试门禁。
7. 建立新线程可以直接续接的实施状态和验证证据。

## 3. 冻结决策与范围边界

### 3.1 设计方向

正式视觉方向保持为 B「和纸墨影」：

- 65% 现代图片画廊。
- 25% 古典日式空间秩序。
- 10% 克制的现代都市氛围。

图片始终是浏览、详情和查看器页面的视觉主角。古典感主要通过比例、留白、细分隔线、材质感和不完全对称构图表达；都市感只通过少量夜蓝、朱砂和低饱和辅助色表达。

### 3.2 不允许改变的内容

- 不修改已有路由地址。
- 不修改后端接口、请求字段、返回结构或数据库字段。
- 不修改权限语义或登录鉴权机制。
- 不删除密码登录、邮箱验证码登录、验证码发送、第三方登录、注册入口、Turnstile 等真实业务能力。
- `/register` 继续作为独立注册路由。
- 不替换 Vue、Element Plus、Pinia 或 Vue Router。
- 不引入大型 UI 框架或新的全局状态管理方案。
- 不重新设计 Logo，不虚构图片、作者、分类、审计或替代文本字段。
- 沉浸式图片查看器继续使用中性深色舞台；认证页面的明亮化不得扩展到查看器。
- 不一次性重写全部页面，不进行全项目格式化。
- 不恢复满屏卡片、大圆角、玻璃拟态、大面积渐变、发光边框或无意义动画。
- 不建立第二套平行设计变量或兼容主题。

### 3.3 允许调整的内容

- 登录和注册页面的视觉构图、内容分组及重复实现。
- 全局设计变量和 Element Plus 尺寸映射。
- 页面区块之间的间距、宽度、对齐和响应式行为。
- 浮层的渲染位置、层级和焦点恢复行为。
- 页面私有组件的拆分边界。
- 测试覆盖和静态设计变量检查。

## 5. 统一布局和组件关系规则

### 5.1 页面结构顺序

除登录、注册和沉浸式查看器外，核心页面统一按以下视觉顺序组织：

1. 页面标题或 Hero。
2. 工具栏、搜索与筛选。
3. 主要内容。
4. 与主要内容直接关联的详情或辅助区域。
5. 分页或后续操作。

不在标题、筛选、统计、分类和图片之间插入无业务意义的装饰面板。

### 5.2 内容关联表达

- 强关联元素使用同一网格、基线、容器或连续背景表达。
- 弱关联元素优先通过留白分开。
- 仅当内容具有明确边界时使用细边框。
- 一个内容组只使用一个主要边界，不在有边框面板内部继续堆叠多层有边框卡片。
- 列表通过行分隔线和间距表达，不把每一行包装成独立悬浮卡片。
- 标签、状态和可清除筛选可以使用胶囊；普通按钮、导航和标题不使用胶囊造型。
- 朱砂色只用于主要操作、危险操作和关键焦点；夜蓝用于导航、辅助选择或低频都市点缀。
- 普通内容区域不使用阴影；阴影仅用于查看器、对话框、抽屉等确实覆盖其他内容的浮层。

### 5.3 间距规则

继续使用现有 `--space-*` 体系，不创建语义重复的间距变量：

- 页面大区块之间：桌面端 48px，紧凑桌面和平板 32px，移动端 24px。
- 双栏或主次面板之间：32px；1024px 以下可降为 24px。
- 同一业务组内部：16px。
- 标签、按钮组和紧密表单字段：8–12px。
- 标题与说明：8px。
- 说明与首个控件：16–24px。

边框不能代替这些间距。

### 5.4 控件高度

新增并冻结：

```css
--control-height-sm: 36px;
--control-height-md: 40px;
--control-height-lg: 44px;
```

使用规则：

- 次要桌面操作：36px。
- 常规搜索、筛选、工具栏和桌面按钮：40px。
- 登录、注册、主要提交操作及移动端触控操作：44px。
- 移动端可交互目标至少 44×44px。
- 图标按钮使用与同级文字按钮一致的方形高度。
- 同一工具栏中的输入框、选择器和按钮保持相同高度和基线。

Element Plus 根级尺寸映射为：

```css
--el-component-size-large: 44px;
--el-component-size: 40px;
--el-component-size-small: 32px;
```

管理员高密度界面在 `.app-shell--admin` 内保留 40/32/24px，不将面向浏览的舒展尺寸强加给审计工作流。

### 5.5 宽度和层级

新增并冻结：

```css
--nav-height: 72px;
--panel-aside-width: 320px;
--panel-drawer-width: 420px;
--auth-form-narrow: 480px;
--auth-form-wide: 640px;

--layer-nav: 100;
--layer-floating: 1100;
--layer-drawer: 1200;
--layer-notification: 2000;
--layer-viewer: 3000;
```

在不超过 900px 的断点下：

```css
--nav-height: 64px;
```

使用关系：

- 普通粘性工具栏低于浮动分页和抽屉。
- 图片抽屉高于页面浮动控件。
- 通知抽屉高于普通业务抽屉。
- 沉浸式查看器始终处于最高层。
- 不再在组件内散落 `z-index: 2000`、`3000` 等无来源数字。

### 6.3 抽屉定位修复

问题根因是抽屉的 `position: fixed` 节点位于 `#app` 内，而 `#app` 使用了 `will-change: transform`，导致固定定位以应用容器而非视口为包含块。

冻结解决方式：

- 保持 `SquareImageDrawer` 为非模态辅助详情，不改成对话框。
- 在组件内部使用 `<Teleport to="body">` 渲染抽屉根节点。
- 保持现有 props、事件和业务请求位置不变。
- 抽屉宽度使用 `--panel-drawer-width`。
- 层级使用 `--layer-drawer`。
- 顶部定位使用正式 `--nav-height`。
- 页面滚动时抽屉始终留在视口内。
- `ImageSquare` 打开抽屉时记录触发元素。
- 关闭抽屉后，如果触发元素仍在 DOM 中，将焦点恢复到触发元素。
- 不将背景设置为 inert，因为该抽屉仍是非模态辅助面板。
- 不锁定页面滚动。
- 390px 下抽屉改为视口内的全宽或近全宽底部/侧滑面板，不能产生横向溢出，关闭控件至少 44×44px。

### 6.4 设计变量清理

补充第 5 节冻结的尺寸、宽度和层级变量，并替换确认存在的旧变量：

|---|---|
| `--black` | `--color-text-primary` |
| `--blue-soft` | `--color-surface-2` |
| `--color-viewer-stage` | `--color-viewer-bg` |
| `--duration-normal` | 根据交互使用 `--duration-standard` 或 `--duration-overlay` |
| `--ease-out` | `--ease-standard` |
| `--gray1` | `--color-canvas-muted` |
| `--gray2` | `--color-border-subtle` |
| `--gray3` | `--color-text-muted` |
| `--leading-body` | `--leading-md` |
| `--shadow-1` | `--shadow-float` |
| `--shadow-3` | `--shadow-dialog` |
| `--text-caption` | `--text-xs` |
| `--text-body` | `--text-md` |
| `--text-small` | `--text-sm` |

组件内部动态属性 `--avatar-color` 和 `--skeleton-ratio` 可以保留，但必须提供明确 fallback，或在设计变量静态测试中列为允许的组件局部变量。

冻结规格：

type ProfileAvatarEditorProps = {

}

- 超过一个页面使用。
- 拥有独立交互状态。
